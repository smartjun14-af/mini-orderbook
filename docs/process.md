## 1. 프로세스 모델 후보 검토 

대표 모델을 본 프로젝트(1인 + AI + 소규모 + 과제 기한) 관점에서 검토:

| 모델 | 특징 | 본 프로젝트 적합성 |
|---|---|---|
| 폭포수 | 단계 순차, 단계 간 중복 없음 |단계가 명확하나 반복 불가가 비현실적 |
| V-모델 | 폭포수 확장, 각 개발 단계에 대응하는 검증(테스트) 강조 | ◎ 테스트 비중 높은 본 프로젝트에 적합 |
| 프로토타이핑 | 시제품으로 요구 확정 |요구가 이미 명확(학습용)이라 과함 |
| 나선형 | 위험 분석 중심 반복 |위험 요소 적은 소규모엔 과중 |
| 진화적 | 점증적 기능 확장 |일부 반복은 채택 |
| 애자일 | 짧은 주기, 문서보다 동작 SW |바이브코딩과 천성은 맞으나, 과제가 문서 산출물을 요구하여 정면 충돌 |

## 2. 선택한 모델과 근거

### 2.1 선택: **V-모델 기반 + 경량 반복(controlled iteration)**

본 프로젝트는 **V-모델을 골격으로 하되, 후속 단계에서 결함·빈틈이 발견되면 이전 산출물을 제한적으로 수정하는 경량 반복**을 허용한다.

```
   요구 분석 ───────────────────────────── 인수/시스템 검증
   (SRS)          \                      /   (사용성 계획)
                   \                    /
    아키텍처 설계 ───────────── 통합 테스트
    (ARCHITECTURE)      \          /    (Integration tests)
                         \        /
     상세/UI 설계 ──────── 단위 테스트
     (DESIGN)          \      /        (Unit tests)
                        \    /
                       구현 (CODING / orderbook.py)
```

### 2.2 선택 근거

1. **검증 강조가 본 프로젝트와 맞는다.** V-모델은 각 개발 단계(요구/설계/구현)에 대응하는 검증 단계(인수/통합/단위 테스트)를 명시한다. 본 프로젝트는 테스트 커버리지 100%·기법별 분류(TESTING.md)로 검증에 큰 비중을 뒀으므로 V-모델의 좌우 대칭 구조와 정확히 부합한다.
2. **단계 경계가 명확해 산출물 추적이 쉽다.** 각 단계가 명확히 끝나고 베이스라인 산출물을 남기므로(형상관리, MAINTENANCE.md), 과제 평가자가 프로세스 적용을 추적하기 좋다.
3. **순수 폭포수의 경직성은 피한다.** 실제로 DESIGN.md를 0.1→0.2로 보강하고, 테스트 커버리지 빈틈 발견 후 테스트를 추가하는 등 반복이 발생했다. 이를 부정하지 않고 "경량 반복"으로 모델에 포함시켰다.

### 2.3 왜 애자일이 아닌가

바이브코딩은 본래는 애자일 모델을 많이 선택한다. (빠른 반복, 동작하는 코드 우선). 그러나 본 과제는 **각 단계의 문서 산출물**(요구·설계·테스트·품질 문서)을 요구한다. 애자일 선언의 "형식적 문서보다 동작 SW"와 정면 충돌한다. 따라서 **AI의 애자일적 본성을 V-모델의 문서·단계 규율로 의도적으로 제약**하는 것이 본 프로젝트의 핵심 설계 결정이며, 이 충돌의 관찰이 곧 "프로세스에 입각한 바이브코딩"의 실험 내용이다.

## 4. 바이브코딩과 프로세스의 결합 방식

각 V-모델 단계에서 AI와 사람의 역할 분담 원칙:

| 단계 | AI 주도 | 사람 주도 |
|---|---|---|
| 요구 | 초안 생성, 누락 점검 | 도메인 정의, 우선순위 결정 |
| 설계 | 다이어그램 형식 변환 | 비자명 시나리오 명세(LL-D3) |
| 구현 | 코드 생성, 리팩토링 | 설계 적합성 판단(LL-C5) |
| 테스트 | 케이스 생성 | 기법 선택·도메인 유추(LL-T4) |
| 품질 | 메트릭 계산 | 임계값 해석·개선 우선순위 |

각 단계의 산출물을 **다음 단계의 프롬프트 앵커**로 사용한다(LL-C1). 즉 SRS→설계 프롬프트, 설계→코드 프롬프트로 연결해 일관성을 확보한다.
