## 1. 도메인 → 유스케이스 매핑 개요

Mini-OrderBook은 코인 자동매매에서 백엔드(전략·주문 라우팅)가 다루지 않는 거래소 측 영역, 즉 호가창 관리와 주문 매칭을 다룬다. 사용자는 자동매매 로직을 학습·검증하려는 개발자/학습자이며, 시스템과의 상호작용은 "주문을 내고, 호가창과 체결 결과를 확인하는" 흐름으로 요약된다.

---

## 2. 유스케이스 분석 

### 2.1 Step 1 — 액터 찾기

| 액터 | 설명 | 근거 |
|---|---|---|
| **학습형 사용자** | 호가창/매칭 메커니즘을 학습·검증하려는 개발자. 주문을 제출하고 결과를 관찰한다. | SRS 페르소나 |

**본 시스템은 외부 시스템(거래소 API, DB 등)과 연동하지 않으므로(SRS Out-of-Scope), 시스템 액터는 존재하지 않는다. 단일 인간 액터로 충분하다.**

### 2.2 Step 2 — 유스케이스 찾기

시나리오(정상 흐름 + 오류/예외)를 묶어 다음 유스케이스를 도출했다.

| ID | 유스케이스 | 유형 |
|---|---|---|
| UC-1 | 지정가 주문 제출 | 핵심 |
| UC-2 | 주문 취소 | 핵심 |
| UC-3 | 호가창 조회 | 조회 |
| UC-4 | 체결 내역 조회 | 조회 |
| UC-1a | 주문 매칭 | 내부(포함) |
| UC-1b | 부분 체결 처리 | 내부(확장) |

### 2.3 Step 3 — 유스케이스 사이의 관계 찾기

관계 정의(포함/확장/대안 흐름)를 적용한다.

| 관계 | 내용 | 정의 부합 |
|---|---|---|
| **«include»** | UC-1(주문 제출)은 **항상** UC-1a(주문 매칭)를 수행 | "다른 유스케이스에서 재사용하도록 캡슐화" → 매칭 로직을 포함으로 분리 |
| **«extend»** | UC-1은 **매칭 후 잔량 > 0 조건일 때만** UC-1b(부분 체결 처리)로 확장 | "기본 흐름이 특정 조건에서 분리 확장" → 조건부이므로 확장 |

## 4. 유스케이스 명세 (시간 순서 기술)

### UC-1. 지정가 주문 제출 (핵심)

| 항목 | 내용 |
|---|---|
| **액터** | 학습형 사용자 |
| **사전조건** | 시스템이 실행 중이다. |
| **사후조건** | 주문이 체결되거나 호가창에 등록된다. |

**기본 흐름**

1. 사용자가 구분(매수/매도), 가격, 수량을 입력하고 "주문 제출"을 누른다.
2. 시스템이 입력값을 검증한다. (side/price/quantity)
3. 시스템이 주문을 생성하고 고유 번호를 발급한다.
4. 시스템이 반대편 호가창의 최우선 호가부터 **가격-시간 우선**으로 매칭을 시도한다. **(«include» UC-1a)**
5. 체결이 발생하면 체결 내역에 기록하고 양쪽 잔량을 차감한다.
6. 잔량이 0이면 "전량 체결"을 표시한다.
7. 시스템이 호가창과 체결 내역을 갱신해 보여준다.

**대안 흐름**

- **A1 (입력 오류)**: 2단계에서 검증 실패 시, 입력부 근처에 오류 메시지를 표시하고 흐름을 종료한다.
- **A2 (부분 체결)**: 5단계 이후 잔량 > 0이면 잔량을 호가창에 등록하고 "부분 체결"을 표시한다. **(«extend» UC-1b)**
- **A3 (미체결)**: 4단계에서 체결 가능한 반대 호가가 없으면 주문 전량을 호가창에 등록하고 "미체결 등록"을 표시한다.

### UC-2. 주문 취소

| 항목 | 내용 |
|---|---|
| **액터** | 학습형 사용자 |
| **사전조건** | 미체결(또는 부분 체결 후 잔량이 남은) 주문이 호가창에 있다. |
| **기본 흐름** | (1) 사용자가 미체결 주문 목록에서 "취소"를 누른다 → (2) 시스템이 해당 주문을 호가창에서 제거한다 → (3) 호가창을 갱신한다. |
| **대안 흐름** | 해당 주문이 이미 체결/취소되어 없으면 `False`를 반환하고 목록을 그대로 둔다. |

### UC-3. 호가창 조회 / UC-4. 체결 내역 조회

| 항목 | 내용 |
|---|---|
| **액터** | 학습형 사용자 |
| **기본 흐름** | 시스템이 현재 호가창 스냅샷(매도 상단/매수 하단, 가격대별 잔량 집계)과 체결 내역(체결가·수량·시각)을 테이블로 제공한다. |

## 5. 일관성 체크 

"유스케이스 명세가 있고 매칭되는 시퀀스 다이어그램이 있는지" 점검한다.

| 유스케이스 명세 | 매칭되는 시퀀스 다이어그램 | 위치 |
|---|---|---|
| UC-1 기본 흐름 (전량 체결) | 완전 체결 시나리오 | DESIGN.md §7.1 |
| UC-1 / A2 (부분 체결) | 부분 체결 시나리오 | DESIGN.md §7.2 |

→ 두 핵심 시나리오가 시퀀스 다이어그램과 1:1로 매칭되어 일관성을 만족한다. (UC-2~4는 단순 흐름이라 시퀀스 다이어그램 생략)
